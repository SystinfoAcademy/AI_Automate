Ce que vous allez construire

Le système de l’Institut Horizon montré pendant l’accompagnement : un chat qui répond en quelques secondes à partir d’un document, et un formulaire traité par une équipe d’agents (qualificateur, rédacteur, vérificateur) avec une validation humaine avant toute réponse. Quatre workflows n8n, une base Supabase, Gmail, Drive et Telegram, construits nœud par nœud.

Durée : environ 8 heures, à répartir sur trois sessions. Chaque étape donne le schéma de ce qu’on construit, la fiche de chaque nœud (nom exact, paramètres, textes à copier), les fichiers à télécharger, un test précis et le résultat attendu. Cochez au fur et à mesure : votre progression reste dans votre navigateur. Un essai par minute (quota Gemini).

Les accès : comptes, clés et identifiants

Tout ce qui sert à se connecter : Gemini, Google (Gmail et Drive), Supabase, Telegram. Chaque identifiant se teste tout de suite : un accès mal réglé coûte dix fois plus cher à trouver plus tard.

Une règle pour toute la page. Les clés, les secrets et les mots de passe ne se saisissent que dans n8n (menu Credentials) ou sur le site du service. Ne les collez jamais dans un message, une capture ou un champ de cette page.

Gemini est le modèle qui lit, qualifie, rédige et vérifie. Sans cette clé, aucun agent ne répond.

  1. Ouvrez aistudio.google.com/apikey et connectez-vous avec votre compte Google.
  2. Cliquez sur Create API key. Si on vous demande un projet : « Create API key in new project ».
  3. Copiez la clé (elle commence par AIza).
  4. Dans n8n : Credentials › Create credential › cherchez Google Gemini(PaLM) Api.
  5. Champ API Key : collez la clé. Laissez Host à sa valeur par défaut.
  6. Nommez l’identifiant Gemini en haut de la fenêtre, puis Save.
Tester
  1. À l’enregistrement, une bannière verte Connection tested successfully apparaît.
  2. Si elle est rouge (Couldn’t connect with these settings) : recopiez la clé, sans espace avant ni après.
Résultat attendu : l’identifiant « Gemini » est listé dans Credentials, sans icône d’erreur.
Si ça bloque
  • Plus tard, l’erreur 429 signifie que vous avez dépassé le quota par minute : attendez une minute. Règle de tout l’atelier : un essai par minute.

Gmail envoie les courriels de validation et les réponses ; Drive donne le document à lire. Les deux passent par la même « application » Google, que vous créez ici une fois.

  1. Ouvrez console.cloud.google.com. En haut, créez un projet (n8n-formation) ou choisissez-en un.
  2. Menu APIs & Services › Library : cherchez Gmail API, Enable. Recommencez avec Google Drive API.
  3. Menu APIs & Services › OAuth consent screen (selon les versions : Google Auth Platform). Si l’assistant s’ouvre : nom n8n formation, votre adresse comme contact, public External, acceptez, Create.
  4. Section Audience (ou « Test users ») : Add users, saisissez votre adresse Gmail, enregistrez. Laissez l’état sur Testing.
  5. Dans un autre onglet, ouvrez n8n › Credentials › Create credential › Gmail OAuth2 API. Repérez la ligne OAuth Redirect URL et copiez-la.
  6. Retour dans Google Cloud : Clients (ou Credentials › Create credentials › OAuth client ID). Type Web application, nom n8n.
  7. Dans Authorized redirect URIs › Add URI : collez l’adresse copiée à l’étape 5, sans la modifier. Create.
  8. La fenêtre affiche le Client ID et le Client secret. Copiez-les dans votre gestionnaire de mots de passe tout de suite : Google ne réaffiche plus le secret ensuite.
Secret perdu ? Ouvrez le client dans Google Cloud › Add secret : un nouveau secret est créé. Ressaisissez-le ensuite dans les identifiants n8n.
Tester
  1. Le Client ID se termine par .apps.googleusercontent.com.
  2. APIs & Services › Enabled APIs : Gmail API et Google Drive API sont listées.
  3. L’état de publication affiche Testing et votre adresse figure parmi les utilisateurs de test.
Résultat attendu : un Client ID et un Client secret enregistrés en lieu sûr.
Si ça bloque
  • Les noms de menus changent selon les versions : cherchez « OAuth » dans la barre de recherche de la console.
  • Pas de bouton Add users : l’application est en « Internal » ; reprenez l’étape 3 en choisissant External.

On donne maintenant à n8n la permission d’utiliser votre boîte et votre Drive, par le client créé juste avant.

  1. n8n › Credentials › Create credential › Gmail OAuth2 API : collez le Client ID et le Client Secret.
  2. Cliquez sur Sign in with Google, choisissez votre compte (celui des utilisateurs de test).
  3. Écran « Google hasn’t verified this app » : c’est normal, l’application est la vôtre. Advanced, puis Go to … (unsafe).
  4. Cochez toutes les autorisations demandées, puis Continue.
  5. Retour dans n8n : Account connected. Nommez l’identifiant Gmail, Save.
  6. Recommencez avec Google Drive OAuth2 API (mêmes Client ID et Secret, même adresse de redirection). Nom : Google Drive.
Tester
  1. Gmail, essai réel. Créez un workflow brouillon : Manual Trigger › Gmail, Send a message (Credential : Gmail ; To : votre adresse ; Subject : Essai ; Message : Essai). Execute workflow : le courriel arrive dans votre boîte.
  2. Drive, essai réel. Dans le même brouillon, ajoutez Google Drive, Search files and folders et cliquez sur Execute step : la liste de vos fichiers s’affiche.
  3. Supprimez ensuite le workflow brouillon.
Résultat attendu : un courriel d’essai reçu et une liste de fichiers Drive affichée dans n8n.
Si ça bloque
  • Access blocked / not verified : votre adresse n’est pas dans les utilisateurs de test.
  • redirect_uri_mismatch : l’adresse de redirection saisie dans Google n’est pas celle de n8n, au caractère près.
  • invalid_grant ou « token expired » : en mode Testing, Google coupe la connexion au bout de 7 jours. Rouvrez l’identifiant, Sign in with Google. Pour un usage personnel, l’état « In production » évite cette coupure.

Supabase est la mémoire documentaire : le document de l’Institut y sera rangé en morceaux, et le chat comme l’orchestrateur y chercheront.

  1. supabase.com › New project : nom horizon, mot de passe de base de données (générez-en un et gardez-le), région proche de vous, plan Free. Create, attendez environ deux minutes.

  4. Dans n8n : Credentials › Create credential › Supabase API. Host : le Project URL, sans « / » final. Service Role Secret : la clé secrète. Nom : Supabase. Save.

Avant de construire : le vocabulaire et les gestes




Les gestes dans l’éditeur


  • Ajouter un nœud : cliquez sur + (ou touche Tab), tapez son nom (ex. « Edit Fields »), cliquez sur l’action voulue.
  • Renommer : cliquez sur le nom en haut du panneau du nœud, ou touche F2.
  • Relier : tirez le point de sortie (à droite) d’un nœud jusqu’au point d’entrée du suivant. Un nœud ajouté depuis le + d’un autre est relié automatiquement.
  • Sous-nœud (modèle, mémoire, outil, parseur) : cliquez sur le + sous l’agent, à côté de la prise voulue.
  • Enregistrer : Ctrl+S. Faites-le souvent.




Saisir une expression


Les textes qui contiennent {{ … }} sont des expressions. Survolez le champ, choisissez Expression (au lieu de Fixed), puis collez le texte. Les blocs « Texte à copier » de cette page sont déjà au bon format.

B · Lexique


MotCe que c’est
NœudUne brique du workflow : un déclencheur, une action, un agent.
ItemUn élément de donnée qui circule d’un nœud à l’autre (ici, une demande).
CredentialUn identifiant enregistré dans n8n (clé, connexion Google…), choisi dans chaque nœud concerné.
ExpressionUn texte calculé, entre {{ }}, qui lit les données d’un autre nœud.
AgentUn modèle d’IA avec une consigne, des outils et une boucle : il décide quoi faire.
Outil (Tool)Une capacité que l’agent décide d’appeler : lire une table, chercher une documentation, solliciter un autre agent.
System MessageLe rôle et les règles de l’agent. Le Prompt, lui, est la demande reçue.
Output ParserImpose le format de la réponse (des champs précis) pour que la suite du workflow puisse la lire.
EmbeddingUne « carte du sens » d’un texte : une suite de nombres qui permet de comparer des textes par leur sens.
Exécution test / productionTest : lancée par vous dans l’éditeur. Production : déclenchée par la vraie adresse d’un workflow publié. L’alerte ne part que pour la production.
PublierActiver le workflow pour qu’il réponde en continu. À refaire après chaque modification.

D · Ce qui peut différer chez vous


  • Les noms de menus de Google Cloud, de Supabase et de n8n évoluent : cherchez le mot-clé indiqué (OAuth, API Keys, Credentials).
  • Les noms exacts des options des nœuds (Guardrails, Supabase Vector Store, Data Loader, Form Trigger) peuvent varier légèrement selon la version de n8n. En cas de doute, le raccourci d’import donne la configuration de référence.
  • L’import CSV dans les Data tables dépend de la version de n8n.
  • Le comportement exact du Scribe et du Vérificateur dépend du modèle : si un verdict diffère de celui annoncé, lisez la justification et ajustez la clé regles de Config.
  • Les schémas et maquettes de cette page sont des illustrations schématiques, pas des captures d’écran.
